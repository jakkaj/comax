# Fix FX001: Detection & restore correctness pass

**Created**: 2026-05-23
**Status**: Proposed
**Plan**: Standalone (comax has no plan repo; single-file CLI)
**Source**: Validation session 2026-05-22/23 against live tmux state — 12 panes failed to restore correctly post-reboot; subsequent `discover_all` cross-check surfaced an additional false-positive
**Domain(s)**: `discovery`, `restore`, `infra` (functional sub-areas of `src/comax/cli.py` — comax is not modelled as a multi-domain repo)

---

## Problem

Comax saved 45 agents correctly, but `--restore` left **12 panes broken** after reboot. Root causes are three independent bugs that compounded into a silent-failure pattern: (1) a substring-match in copilot detection mistakes any process whose argv merely *mentions* "copilot" for a real copilot, (2) `tmux send-keys -t <session>:<window-name-with-dots>` is misparsed by tmux as a window-pane index expression and the resume command never lands, (3) `run()` discards `stderr` and `returncode` so the restore table prints `OK` even when send-keys failed entirely. On top of those, stale session UUIDs and a shell-init race produce extra silent failures.

## Proposed Fix

Replace the substring detector with an argv[0]/argv[1] binary-name check (covers the `node /path/to/copilot` wrapper case). Route every restore `send-keys` through PID-based pane resolution so window names containing dots no longer break. Make `run()` return `(stdout, stderr, returncode)` and wire the restore table to report `OK`/`WARN`/`FAIL` truthfully. Pre-validate each saved session UUID against the agent's on-disk store before emitting a resume, so stale UUIDs become `WARN`s rather than half-broken panes. Wait for shell readiness (and refresh the pane PID) before sending the resume command, eliminating the new-window race.

## Acceptance

- [x] **Truthful restore**: invoking `comax --restore` with a fake state.json entry pointing at a nonexistent pane produces a `FAIL` row in the table (currently prints `OK`). _(FX001-1 acceptance — validated 2026-05-23 via `run_full` + `_send_keys_to_pane` unit tests, including bogus-pid → rc=2 and nonexistent-session send-keys → rc=1)_
- [x] **No copilot false-positives**: running `comax --save` while a pi pane has a child whose argv contains the word "copilot" (verifiable with `bash -c 'echo copilot; sleep 30' &` inside a pi pane) saves that pane as `pi`, not `copilot`. _(FX001-2 acceptance — validated 2026-05-23 via reproducer + 11-case unit table + 35-agent regression sweep)_
- [x] **Dotted-name restore works**: a freshly saved state containing a window named `2.1.126` restores into a tmux session of the same name and runs its claude/pi/copilot resume command in that window. _(FX001-3 acceptance — validated 2026-05-23 via end-to-end synthetic state.json run: cookie `FX001_3_E2E_*` landed in pane `comax_fx001_3_e2e:0` (named `2.1.126`) and was echoed by the shell)_
- [x] **Stale-UUID handling**: state.json with a claude UUID whose `~/.claude/projects/*/<uuid>.jsonl` is absent produces a `WARN: uuid stale` row and leaves a clean shell in the saved cwd. _(FX001-4 acceptance — validated 2026-05-23 with a 3-window synthetic state; 2 stale UUIDs each emitted exactly one `WARN: uuid stale` row; zero `--resume` strings ended up in any captured pane scrollback)_
- [ ] **Race-free restore**: with a 500 ms-delayed `.zshrc`, restore still delivers an intact `cd '<cwd>' && <agent> --resume <uuid>` command. _(FX001-5 acceptance)_
- [ ] **Regression budget**: the 33 windows that restored correctly under today's binary continue to restore correctly under the fixed binary; no new `FAIL` or `WARN` rows attributable to the fix.
- [ ] **Manual end-to-end smoke**: after `uv tool install . --force`, the operator runs `comax`, then closes a representative window (e.g. `articles:2.1.138`), then runs `comax --restore`, and observes the window reappears with the agent live (or `WARN: uuid stale` if the UUID has rotated since save).

## Out of Scope (deferred to follow-up fixes)

- **FX002 (proposed)**: Save tmux window topology even when no agent is live (bug #6 — a tmux window the user had quit before save is currently lost). Schema change to state.json.
- **FX003 (proposed)**: Cache `ps -eo pid=,ppid=` once per `discover_all` call (bug #7 — `walk_process_tree` re-runs the full process listing per node). Performance fix.
- **FX004 (proposed)**: Watch/daemon mode that periodically `--save`s without operator action (bug #11). Feature, not a fix.
- **Documented limitation**: pi rewrites argv[0] to `"pi"`, so launch flags (model, thinking, extensions) cannot be recovered on restore (bug #8). README already notes this; no comax-side fix is possible.
